# Crypto Wallet LangGraph Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a non-custodial Python LangGraph service that exposes wallet queries and Bridgers/OmniBridge swap orchestration to a mobile wallet app through REST and SSE.

**Architecture:** FastAPI owns the HTTP boundary, LangGraph owns typed state transitions and resumable execution, provider adapters normalize Bridgers/OmniBridge, and chain adapters expose read-only wallet capabilities. The app signs and broadcasts transactions; the service only prepares unsigned transactions, receives hashes, and tracks provider orders.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, LangGraph, LangChain OpenAI integration, httpx, SQLAlchemy/asyncpg for durable storage, pytest, pytest-asyncio, and ruff.

**Spec:** `docs/superpowers/specs/2026-09-04-wallet-langgraph-agent-design.md`

## Global Constraints

- Backend is non-custodial: never accept or store private keys, seed phrases, signers, or wallet client objects.
- App-local signing and broadcasting are mandatory; `/broadcast` accepts only a chain-qualified transaction hash.
- Checkpointed state is typed, serializable, and contains no live clients or secrets.
- Bridgers and OmniBridge response shapes stay inside their provider adapters.
- Unsupported chain capabilities return `CHAIN_CAPABILITY_UNAVAILABLE`; the model must not fabricate results.
- Every retry loop has a bounded attempt count, timeout, and explicit terminal state.
- Provider writes use idempotency keys; user rejection and validation failures are not retried.
- External APIs run only in explicit integration tests; unit tests use deterministic fakes.
- API-sensitive LangGraph/LangChain code is checked against the configured Context7 MCP or official documentation before implementation.
