## 二、026：转账成功/失败状态卡（重点）

### 现象
App 轮询 `GET /v1/transactions/{chain}/{tx_hash}` 拿交易状态。ERC-20/TRC-20 转账的**失败态与成功态卡片**一直显示错误的「0 ETH」（explorer 无 token 层时原生 value 为 0），金额/symbol 对不上；后续又出现 **token logo 不显示**。

### 根因链
1. 失败态（`b801eae`）：失败转账在 explorer 里通常没有 token 层 → 卡片渲染成原生币「0 ETH」行。
2. 成功态（`6cf5659`）：已确认的 token 转账（如 DAI 自转账）同样无 token 层 → 成功卡也显示「0 ETH」。
3. 匿名回落（`b38eaaa`）：demo 与无 Bearer 的 App 调用没有 `user_id`，回落不生效。
4. **真正根因（`1383291`）**：MySQL 实测测试服全部 38 条带 `broadcast_tx_hash` 的会话中，**所有转账类会话的 `session.asset` 都是 NULL**（只有 swap 会话有 asset）。原因是 ReAct 转账流程 `finalize_response` 只把 `pending_transaction` 提升到 response、**没有提升 asset**，`project_session` 因此拿不到 `response.asset`，`session.asset` 恒为 NULL → 状态卡兜底拿不到真实转移资产。
5. logo（`f995f2f`）：`asset_logo_url` 用会话里存的**小写**合约地址拼 Trust Wallet 链接，而 TW 目录按 **EIP-55 checksummed** 地址命名（GitHub API 实测：USDC checksummed 200 / 小写 404，DAI 同理）→ 图片 404，卡片不显示 logo；成功卡场景 explorer 返回了 token 层但没带 icon 时也缺回落。

### 修复
- `b801eae`：失败态回落会话转移资产（transfer_draft/session.asset），状态卡渲染真实 DAI/USDT 金额与 icon。
- `44df7cb`：金额卡 25/50/75/100% 携带所选链的真实余额（V169-IOS-018）。
- `6cf5659`：confirmed 的 token 转账（无 token 层）也回落；原生转账保留 explorer 真实金额。
- `b38eaaa`：匿名 `user_id` 时按 `broadcast_tx_hash` 全局回落（`find_by_broadcast_tx_hash`）。
- `4e3e54c`：用户输入 `Ox…`（字母 O）前缀归一化为 `0x`，完整转账可直接准备。
- `1383291`：`finalize_response` 提升 `asset` + `chain_logo_url` 到 response，`project_session` 持久化 `session.asset`（**根治 NULL**）。
- `f995f2f`：`asset_logo_url` 对 EVM 地址做 EIP-55 checksum（TRON base58 透传）；成功卡 explorer 有 token 层但无 icon 时从 session 资产推导 logo；OKX explorer adapter 一并受益。

### 验证
- 新增/更新回归测试（ReAct 转账 asset 持久化、状态卡 DAI/USDT 回落、checksummed logo、token 层无 icon 回落）。
- 线上实测：失败 USDC 交易状态接口返回 checksummed logo + 正确 symbol/amount。
- **用户已确认成功/失败卡片问题解决。**

## 三、转账/余额卡片交互

### 现象
「把以太坊上的全部 dai 转到 0x3F84…」——用户已给出**完整转账意图**，但 App 先弹**余额卡片**，等用户说「转账啊」才弹出转账卡片。

### 根因
1. 收款地址是用户自己 → 模型检测到 **SELF_TRANSFER** 后停下，调 `wallet_balance` + `transfer_quick_replies` 并问「确认要这样转吗？」，先展示余额卡，阻塞到用户再次确认。
2. `finalize_response` 只要本轮调了 `wallet_balance` 就投影 `portfolio`（余额）卡——即使同轮已准备好转账也会同时渲染余额卡。
3. 潜在 bug：`_transfer_draft_request` 用 `dict.setdefault` 合并 `transfer_*` 别名，但 `setdefault` 只在键**缺失**时生效；`react_prepare_transfer` 传 `token_address=None/decimals=None` 时不会被提升，导致 token 转账报「参数缺失」无法准备。

### 修复（`84624ad`）
- **system prompt**：用户已给出完整转账参数（币种 + 数量/全部 + 收款地址）时直接 `prepare_transfer`，不先查余额、不因自转账停下追问（SELF_TRANSFER 等警告由转账卡片 preflight 自动展示）。
- **finalize_response**：本轮已准备好转账时不再投影 `portfolio` 余额卡（转账卡取代余额卡）。
- **_transfer_draft_request**：`transfer_*` 别名改为 **None 感知合并**（显式 None 视同缺失）。

### 验证
- 新增 `test_react_prepared_transfer_supersedes_balance_card`（同轮 balance + prepare → 只有转账卡、无 portfolio）。
- 全量测试绿，已部署 catwallet-test 容器内确认三处修复在。

## 四、兑换/历史/i18n/到账 等其他修复

### `32eeb0c` fix(swap/history)（V169-IOS-023 / 022 / Lif 历史卡反馈）
- Swap 报价：App 8 位小数 half-up 的「100% 余额」金额超出实际余额 ≤1 个显示单位时，把 `input_amount_raw` clamp 到钱包余额，避免确定性 preflight 误报 `INSUFFICIENT_BALANCE`。
- Swap 会话：`amount_mode` 以 `exact_in/exact_out` 枚举暴露；非法模式返回 `INVALID_AMOUNT_MODE`；换源资产时清掉携带过来的旧金额（此前 ETH 金额被当作 USDT 输入复用）。
- 交易历史：「共 N 笔」改为描述**展示的**行数；native 行缺失 decimals 时继承链精度，模型可换算 BTC/TRX 金额。

### `f8feda5` / `4ff65e7` fix(i18n)
- 状态卡（broadcast、swap order）不再硬编码中文：`not_propagated / unknown / dropped_or_replaced`、`status_poll`、prepare/cancel 等全部本地化，避免中英混排。
- 按会话语言（en/zh）下发状态文案：在 `SwapSessionRecord` 持久化语言，broadcast 与状态卡文案随语言分支（默认 zh，可回退会话历史）。

### `30c5773` fix(swap/status)
- 已签名兑换后的「到账了没有？」短追问，之前走了 ReAct 用 `transaction_history` 回答；现在 `react_entry` 在 prompt 中暴露进行中订单，模型用 `query_swap_status` 查订单，返回**兑换订单数据**而非最近交易流水。

### `5383d8b` fix(react/balance)
- 转账草稿未完成时查询余额，之前会误触发 `prepare_transfer`（TOOL_FAILED）；现在纯余额/资产查询只调 `wallet_balance/portfolio_snapshot`，`react_prepare_transfer` 用 `_looks_like_balance_only_query` 兜底返回 `TRANSFER_NOT_REQUESTED` 跳过，草稿保留给显式续转。

### `7b62865` chore(env)
- 测试服上 `*.llamarpc.com` / `polygon-rpc.com` 在数据中心 IP 不稳定（DNS 失败 / 401/403），导致 transfer preflight 报 `FEE_ESTIMATE_UNAVAILABLE`；换成 publicnode/drpc/1rpc 等稳定公共 RPC，并核对 ARBITRUM 链上余额。
